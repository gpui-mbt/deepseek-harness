# Agent Note: Web GUI 的手机宽度外壳

Status: implemented

[English](2026-10-18-mobile-web-shell.md) | 中文

## 问题

Web GUI 是为桌面窗口设计的固定高度三栏应用。在手机宽度的 Safari 窗口中，它保留 56px 导航栏（在 390px 屏幕上给会话留下 334px），按布局视口确定挂载点尺寸，忽略刘海与 Home 指示条，并且在输入框获得焦点时让 iOS 缩放页面。

其中四项是平台行为而非样式问题：视觉视口会在不改变布局视口的情况下缩小（软键盘、收起的工具栏、双指缩放）；`viewport-fit=cover` 让内容进入刘海与 Home 指示条区域；iOS Safari 忽略 `user-scalable=no`，并把任何小于 16px 的已聚焦文本控件所在页面缩放；在外壳上下拉刷新会重新加载页面，丢弃实时连接与草稿。

## 决策

### 挂载点跟随视觉视口

`dsh-client-web` 将视觉视口高度发布为 `--dsh-viewport-height`（回退到 `innerHeight`），并在可见高度比布局高度短至少 120px 时标记 `html[data-soft-keyboard]`；外壳样式表据此设置 `#root` 高度。不投影视觉视口的 `offsetTop`：页面主体不滚动，字段获得焦点时 Safari 不会平移页面，而平移挂载点会移动每一个自行计算定位的固定浮层。浮层通过 ui-primitives 的 `visibleViewport()` 约束到同一可见矩形，因此在键盘之上打开的菜单仍然可达。

### 安全区只发布一次

`--dsh-safe-top`、`-right`、`-bottom`、`-left` 取自根元素上的 `env(safe-area-inset-*)`。框架应用垂直方向，侧边栏列、抽屉、中栏标题与输入区、全屏右面板应用水平方向，因此全出血浮层为自身内容留出内边距，而不是被框架内缩。键盘打开时底部安全区归零，因为键盘覆盖了 Home 指示条。

### 768px 是手机断点

低于 768px（右侧面板已改为全屏覆盖的宽度）时，左侧导航成为抽屉：框架不为它保留轨道，去掉控制栏，并替换同一侧边栏元素的 class，因此跨过断点占用方保持挂载，滚动位置与 store 都不丢失。框架在此挂载 `shell.leading` 座，让 ui-sidebar 已有的重新打开与新建会话控件落在标题栏起始角。手动展开的导航在跨过 768px 或 1024px 时清除，因为展开状态在另一侧是另一种界面。768–1024px 保留列与控制栏。

两侧界面也可通过边缘滑动打开，并朝它来时的边缘拖回而关闭，实现位于 ui-primitives 的 `installEdgeSwipe` 与 `installSwipeDismiss`：从可见视口边缘 24px 内起始、完成距离 48px，并在移动 10px 后判定轴向；垂直拖动、允许区域外起始、起始于已打开抽屉、遮罩或对话框的触摸，以及起始于水平滚动内容或 docking kit 标签/分隔条上的关闭拖动，都留给浏览器。每个监听器只在对应界面处于该手势所改变的状态时存在。iOS Safari 自身的返回手势占据最左侧边缘，因此那里仍以标题栏控件为可靠入口。

### 触摸端文本输入有下限

粗指针设备上文本输入控件至少计算为 16px。iOS Safari 会为更小的字号缩放页面并忽略 `user-scalable=no`，因此这是唯一保留双指缩放的修法。规则位于外壳样式表并优先于功能样式表（后者保留桌面尺寸）；输入卡片随之调整，使占位符与工具栏跟随草稿一起变化。

## 备选方案

- **在 768px 以下保留 56px 控制栏。** 控制栏占 390px 框架的七分之一，展开后把会话压缩到 110px。抽屉让会话保持全宽，并保留同样的导航内容。
- **把抽屉断点设为 1024px。** 这会替换掉仍有空间的桌面窗口的列。768px 已经是右侧面板停止推挤、覆盖框架的宽度，两侧边栏因此在同一宽度切换呈现方式。
- **用 `maximum-scale=1` 阻止聚焦缩放。** iOS 会忽略 `user-scalable=no` 的聚焦缩放判断，而禁用双指缩放会移除用户依赖的无障碍缩放。16px 下限保留双指缩放。
- **按视觉视口 `offsetTop` 平移挂载点。** 被 transform 的 `#root` 会成为其固定后代的包含块，挂在 body 上的浮层不再与它共享原点。页面主体不滚动，所以在本外壳产生的状态中该偏移保持为零。
- **让所有指针设备都保留 `overscroll-behavior: none`。** 一旦根滚动容器拒绝链接，Chromium 会把 Home 与 End 交给它而不是聚焦的编辑器，使输入框光标滞留。下拉刷新只存在于触摸端，因此约束只在那里生效。

## 影响

- `apps/web/tests/mobile-shell.e2e.ts` 承载手机框架契约：没有整页横向溢出、挂载高度等于视口、抽屉从起始座或边缘滑动打开并在 Escape、遮罩、自身反向拖动或它所揭示的界面关闭、输入区位于可见矩形内且文本为 16px、右侧面板由标题栏控件或尾侧边缘滑动打开并全屏、由反向拖动关闭。
- `composer-focus.e2e.ts` 是塑造 overscroll 规则的那次回归；它在细指针下覆盖 Home、End 与光标复原。
- 768px 以下设置面板变为全出血，并带横向分区条。目录选择器、模型菜单与右侧面板由同一端到端场景在 390px 下验证。
- 横向手机达到 844px，保留控制栏布局。若需重新审视该取舍，`packages/client/ui-layout/src/client/columns.ts` 中的 `MOBILE_MAX` 是唯一要改的值。
- 安装界面随该决策一起交付：`display: standalone`、由内置 favicon 生成的 192/512 maskable PNG、`apple-touch-icon`，以及 iOS 的 capable/title meta。`theme-color` 仍由主题呈现器拥有。
