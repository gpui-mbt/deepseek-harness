# Agent Note: 永続 dot は内蔵パッケージ

Status: implemented

[English](2026-10-26-dots-in-box.md) | 中文

## 問題

[dsh-dots](https://github.com/f4ah6o/dsh-dots) は外部バンドルとして出荷されていました。独自ワークスペース、独自の `@f12o` パッケージ、Remote プレーンの隣に並ぶブラウザ API ルート、`hosts.json` の fleet レジストリ、ホスト間でレコードを複製する peer トランスポートを持っていました。DSH のプレリリースごとにパッケージは peer バージョンを再ピンし、クライアントは他のすべてのパネルが使う Typert Remote ではなく、独自の fetch エンベロープで `/dots/api` と通信していました。

機能を内蔵化するにあたり、外部レイアウトが別の答えを出していた 4 つの問いが生じました。製品が単一ホストになったとき、マルチホストのライフサイクルはどこに置くのか。廃止するファイルレジストリを、レコードを失わずに耐久ストレージへ移すにはどうするか。組み込みのプロンプト API が 1 つのメッセージソースしか持たないとき、割り当てをどう届けるか。実行ガードを dot の子孫にまで及ぼすにはどうするか。

## 決定

### 単一ホスト、Web アプリの行

`@deepseek-ai/dsh-dots` は `packages/bundle/web-app/cordis.patch.yml` の `session-controller` の後にマウントされ、`@deepseek-ai/dsh-tool-dots` がその隣に並びます。どちらも Session controller を必要とし、それを組み合わせるのは Web ホストだけです。peer/fleet 層はなくなりました。`hosts.json` も `host` 引数もリモート選択もミラーリングもありません。dot は保存したホストが所有し、レコードはそのホストのストレージドメインに残ります。クライアントパネルは同じバンドルの `@deepseek-ai/dsh-client-ui-dots` として出荷されます。

### レコードはストレージドメインへ移り、一回限りで取り込む

レコードは `dots` ストレージドメイン（バージョン 1）の `DotId` キーの 1 テーブルに保存され、ファイルレジストリと同じデコーダで検証されます。初回有効化時、テーブルが空の間に `$DSH_HOME/dots/registry.json` を取り込み、ファイルを `registry.json.imported` に改名します。空でないテーブルの隣に残ったファイルはログに記録され、そのまま残ります。暗黙のマージもユーザーデータの削除もしないため、取り込みに失敗してもファイルを戻せば復旧できます。

### 割り当てはキューイングされたプロンプト

`sessionController.prompt({ mode: 'queue' })` が組み込みで唯一の配信経路です。プロンプトフレームは dot 名と id、目的、割り当て id、呼び出し元、上限付き `MEMORY.md` 末尾、タスクを運びます。`lastAssignedAt` と `assignmentCount` は受け入れ後にのみ記録されます。組み込みのプロンプト API は通常の `user-rpc` メッセージソースを記録するため、dot id は `source.kind === 'dot'` イベントではなく本文に載ります。1 つの消費者のために新しいソースを追加すると Session 形式が変わるため、形式を変えない代わりに識別子をテキストで運びます。

### ガードは dot の子孫に及ぶ

外部のガードは dot のホームセッションだけを対象に `dot_*` を拒否し `allowedTools` を強制していました。内蔵版では、ガードが `parentSessions` ポート経由で生きたセッションの系譜を解決し、そこから派生した subagent セッションにも dot の許可リストを適用します。dot が dot を管理できない点は変わりません。これは外部契約が記述しながら実装していなかった経路を塞ぐものです。

### Remote サーフェスは意図的に小さい

`dotsController` Remote サービスは `list`、`create`、`assign`、`update`、`archive`、`scheduleList`、`scheduleCreate` を公開します。パネルとツールの両方が必要とする操作です。モデル選択は `create` が受け取りライブカタログに対して検証しますが、カタログを公開する Remote メソッドはありません。Web パネルはデプロイの既定値を使い、ブラウズ UI は先送りです。

## 検討した代替案

- **peer/fleet 層をフラグの背後に残す。** 製品には第 2 ホストの所有者もトランスポートもありません。フラグは未テストのコードと、Remote プレーンを迂回するブラウザ API ルートを温存するだけです。
- **ファイルレジストリを残しストレージのミラーを追加する。** 1 レコードに 2 つの権威が生まれ、乖離を招きます。一回限りの取り込みは単一の権威と可逆な切り替えを与えます。
- **`dot` メッセージソースを追加する。** 識別子は型付きになりますが、1 つの生産者のために Session 形式が変わります。プロンプトフレームは形式を安定に保ちます。
- **モデルカタログを Remote で公開する。** ピッカーには有用ですが、外部パネルのモデルブラウザは移植作業の最大部分で、現時点で内蔵の消費者はいません。
- **HTTP `/dots/api` ルートを残す。** Remote 名前空間は認証・キャンセル・型付きエラーをすでに運びます。2 つ目のルートは認証サーフェスを重複させます。

## 結果

- 内蔵行をマウントする前に外部バンドルを削除する必要があります。`dotsController` の二重登録は明示的に失敗します。[移行ガイド](../../../../docs/upgrade-guide/v0.2.1-rc.2/dots-in-box/guide.zh.md)が移行と registry 取り込みを所有します。
- ストレージの権威は 1 つになり、不正な行はライフサイクルに入るのではなくドメインのオープンを拒否します。
- ガードは subagent の子孫まで対象になり、これは外部ソースが記述しながら実装していなかった部分です。
- モデルピッカー、ホストセレクタ、peer 層は先送りです。パネルはデプロイ既定値と単一ホストを使います。
- クライアント側の日本語コピーは他のすべての名前空間と同様、`@deepseek-ai/dsh-client-locale-ja` に置かれます。
